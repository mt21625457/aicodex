## 根因与责任层

上游修改了认证归属、模型目录初始化、会话恢复、回合结束及媒体接口；
本地同时扩展了历史元数据、压缩预算、第三方模型和错误终态。
Git 无冲突的自动合并也可能留下旧构造参数、未覆盖枚举及失效的调用方。
锁文件、协议产物和场景快照不能通过单边覆盖证明兼容。

另发现 Python SDK 的模拟服务夹具只设置 `CODEX_HOME`，没有隔离
`AICODEX_HOME`，并允许使用已有 release 二进制。这样无法保证测试读到
临时目录中的模拟提供商配置。夹具现同时设置两个 home，新增
`test_harness_isolates_both_runtime_home_names`；最终运行必须显式指定本次
构建的 `CODEX_EXEC_PATH`，不能以旧构件的结果评价合并源码。

## 合并合同

1. 用户已确认采用会话绑定原提供商：更改默认提供商不改写旧会话路由；
   保留配置存在性、托管策略校验，以及有边界的 DeepSeek 旧网关别名迁移。
   新增 `default_provider_change_preserves_saved_thread_route`，覆盖已加载
   会话和进程重启后的恢复，并断言替代提供商未收到请求。
2. 保留 CORE-001 的公开 number schema、请求副本历史兼容、
   `invalid_request_error` 终态及 `badRequest` 映射。上游新增的预算、
   inference hook、workspace、access program、音频分类仍使用专用语义。
   普通非 408/429 客户端错误仍不可重试；分类与重试是两个独立断言。
3. 保留 CORE-002 的压缩总预算、历史保留和本地估算边界；重试使用上游
   Retry-After 绝对截止时间，同时经过本地 watchdog 的剩余预算准入。
   DeepSeek 前缀记录位于每次流建立后，兼容上游重采样闭包的生命周期。
4. 认证归属使用上游 `AuthOwner`，保留跨提供商隔离；
   模型目录结合初始化/更新通知与本地显示缓存，不让慢缓存覆盖新网络结果。
5. 上游已移除用户配置中的 Guardian extra-policy/template 和 MCP
   auto-deny 开关；沿用其显式弃用提示与新策略入口，不恢复过期接口。
   Guardian 明文推理仍整项保留或省略，不在单项内截断。
6. 上游拆分的测试文件采用三方迁移保留本地回归；协议稳定/实验产物及
   Python 类型从合并后的 Rust 定义生成。
