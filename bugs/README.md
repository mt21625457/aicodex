## 记录和关闭要求

1. 每个问题使用稳定编号 `CORE-NNN` 和独立 Markdown 文件；保留已分配编号，新增记录同步索引。
2. 写清症状、触发条件、已观察证据、责任层与修复边界；区分已验证、推断和未验证，不把多个不同原因的失败合并解释。
3. 给出能在旧行为下失败的聚焦测试、对应源码入口和可执行验证命令；协议升级同时列出新会话与旧数据恢复场景。
4. 记录修复提交与验证范围。源码、集成、真实服务、安装验收分别说明；不能把新会话 smoke、HTTP 200 或打包成功当成全链路通过。
5. 禁止提交令牌、认证头、真实聊天或用户数据副本。使用合成 fixture；真实数据只在已授权范围内使用。
6. 根因或验收状态有新证据时更新原记录；后续扩展不得删除仍有效的回归保护。
