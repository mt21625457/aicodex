# 提交前复审与修复

本次复审覆盖全部未提交生产改动、测试、基准工具和证据；三路独立复审分别检查请求/模型、
缓存/索引、viewer/验证工具。基线仍为 `daf61e7a3d08c004cce53df531094a69795da819`。
首次实施数据保留在 [原报告](performance-followup-results.md)，没有用新样本覆盖旧样本。
本文件记录最终代码和测量差异。

## 修复的问题

1. **无关工具输出影响 shell 缓存接纳。** 原候选预扫描把所有大工具输出计入容量上界。
   16 个有效 shell 结果混合 17 个无关大结果，会被误判为大集合并限制每轮只接纳一次。
   修复为两阶段判定：上界不超过 16 时保留原快速路径；超过时借用 call_id 核对真实配对，
   找到第 17 个真实候选即停止。小结果同样先消费配对，避免重复大结果被重新计入。
   预扫描和转换共用调用类型识别，保留 Local call_id 优先/legacy id 回退、function
   shell/apply_patch 和 custom apply_patch。新增确定性解析次数及调用类型回归。
2. **基准二进制与 manifest 可能不一致。** components/lazy 的 run-only 现校验实际执行文件
   SHA256，拒绝目录复用或中断重建留下的新二进制配旧源码摘要。
3. **持续通知可绕过等待超时。** app-server runner 现在每次取队列前检查绝对截止时间，
   非目标通知不延长总等待上限。
4. **不等价样本提前写入成功结果。** 完整请求、归一化路径及输出摘要全部一致后才发布整对样本；
   新运行先清空上一轮结果，首对失败不会保留旧的成功文件。空/负工作量在启动前拒绝。
5. **异常清理不完整。** 组件探针中断或等待异常时终止并回收子进程；mock HTTP 服务的清理
   覆盖配置写入、Popen 失败等路径。

未发现模型目录身份门控、惰性预算、viewer 持久化/错误处理或历史 revision 失效的确定新增
功能问题。日志裁剪、跨追加索引和 Markdown fallback 的生产算法继续保留。

## 最终 shell 矩阵

相同方法：5 轮、每轮 400 次，真实源码提取，包含输入克隆及逐次完整输出等价断言；
两版交替运行，计时期间没有 Cargo 或其他基准任务并发。原始五个候选全部重跑，共 225 个样本。
下表展示原始基线和最终实现的中位数，完整候选数据见 `review-shell-results.json`。

| 场景 | CPU，前→后（ms/400 次） | JSON 解析，前→后 | 累计申请字节，前→后 |
|---|---:|---:|---:|
| 暖 16 项 | 50.930→50.822 | 0→0 | 110,288,800→110,288,800 |
| 暖 17 项 | 310.425→75.767 | 6,800→777 | 285,792,000→130,245,565 |
| 暖 32 项 | 583.916→216.085 | 12,800→6,777 | 537,948,000→283,221,529 |
| 暖 128 项 | 2,334.370→1,121.139 | 51,200→45,177 | 2,151,824,800→1,262,335,009 |
| 16 shell + 17 无关大输出，冷启动后重放 | 54.895→55.481 | 16→16 | 178,209,228→178,239,628 |
| 1000 项小输出 | 345.155→355.355 | 400,000→400,000 | 490,179,200→490,179,200 |

混合工具场景首次转换后，第二轮解析次数为 0。新增配对核查在该样本中每次增加一次临时
分配和 76 B 申请量，CPU 比基线约高 1.1%；不能宣称修复没有成本。对应额外存活堆峰两版
均为 586,097 B。暖 17 项的额外堆峰两版均为 177,428 B。

1000 项小输出的 CPU 中位数约高 3.0%，申请量与峰值不变；仍有候选预扫描成本。
本轮不通过删除小输出测试或挑选较快轮次掩盖取舍。大量无效 JSON 的负缓存成本和 128 项
时完全绕过缓存可能更快的边界仍存在；有限接纳不能称为所有负载上的最佳方案。

## 最终完整应用复测

最终二进制按相同 dev 配置重建，继续使用隔离状态和固定本地 SSE 服务，7 组交替运行，
每组 40 个 turn、每个输入附加 16,384 字节。完整请求及助手输出均通过等价检查。

| 指标 | 基线中位数 | 最终实现中位数 | 变化 |
|---|---:|---:|---:|
| 进程 user+system CPU | 2.981967 s | 2.900618 s | −2.73% |
| 每轮 turn P50 的中位数 | 23.259 ms | 22.643 ms | −2.65% |
| 每轮 turn P95 的中位数 | 31.848 ms | 29.426 ms | −7.61% |
| 进程最大 RSS | 201,687,040 B | 200,491,008 B | −0.59% |

CPU 样本区间为 2.874–3.121 s 和 2.875–3.033 s，明显重叠。与首次测量的幅度不同，
没有建立统计显著性；这些数据仅说明该本地负载的观测，不能归因为修正 shell 配对带来的
额外应用收益（此负载不触发 shell），也不能承诺通用加速。
整进程分配未插桩，release、Windows、真实网络/WS及高并发服务没有验收。
优化版新路径首轮初始化仍约 9.77 s；保留样本，首次报告已有两版新路径首启复现记录。
