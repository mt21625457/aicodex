# 性能优化实施与差分验证（2026-10-23）

本文件保留首次实施的测量快照。提交前复审又修正了混合工具的 shell 候选判定和基准工具异常路径；
最终代码、补充验证与重新测量结果见 [提交前复审](performance-review-fixes.md)。

基线为 `daf61e7a3d08c004cce53df531094a69795da819`，分支 `dev`；开始时工作区干净。
本轮由 8 个不同 agent 分批实施、设计验证和独立审核，大型 Cargo 构建始终串行。
代码尚未提交。没有读取真实 API 凭据或调用真实模型服务。

结论：五项生产优化已实现，组件重复工作显著减少；完整本地 app-server 实验只观察到
较小的 CPU 和中位延迟改善，尚不足以证明通用整应用加速。日志裁剪、跨追加索引复用、
Markdown 依赖图完成设计与反例验证，未替换生产算法。

## 组件实测

macOS ARM64，`rustc 1.96.0`。真实源码提取探针用 `rustc -O`，复用现有依赖产物，
不等同于产品 release 构建。每个场景 5 轮，before/after 顺序交替，表中是批次中位数。
计时期间没有 Cargo 或其他基准任务并发，普通桌面后台服务仍在运行。

“申请量”是 Rust allocator 累计请求字节，不是常驻内存；“堆峰增量”是相对测量开始
时存活分配的增量峰值，不包含 allocator 保留页。计数器和等价断言存在开销。
下面的百分比只属于对应组件负载。

| 场景与操作数 | 区间 CPU 时间，前→后 | 分配调用，前→后 | 累计申请字节，前→后 | 堆峰增量，前→后 |
|---|---:|---:|---:|---:|
| 内置目录精确选择，20,000 次 | 297.096→29.517 ms（−90.1%） | 6,140,000→700,000 | 9,977,040,000→1,239,420,000 | 498,852→61,971 B |
| 1 MiB viewer 暖命中，200 次 | 95.593→15.403 ms（−83.9%） | 7,600→1,400 | 5,383,652,200→209,833,200 | 16,084,611→1,048,911 B |
| 无需预算估算，50,000 次 | 175.609→1.630 ms | 100,000→0 | 4,245,950,000→0 | 84,791→0 B |
| 需要预算估算，50,000 次 | 174.347→176.788 ms（+1.4%） | 100,000→100,000 | 4,245,950,000→4,245,950,000 | 84,791→84,791 B |
| 200 万行历史暖尾查，100 次 | 1,542.766→1.124 ms | 400→400 | 7,380,900→7,076,800 | 73,809→70,768 B |
| 17 个不同 shell 输出重放，400 次 | 309.687→75.276 ms（−75.7%） | 75,600→50,754 | 285,792,000→130,215,165 | 177,428→177,428 B |

补充机制与延迟证据：

- 目录：每次复制申请从 498,852 B 降到 61,971 B；操作 P50 14.542→1.458 µs。
  探针覆盖目录函数和精确选择；完整 ModelsManager 的身份门控、配置和匹配由回归测试覆盖。
- Viewer：操作 P50 468.167→75.583 µs；整个探针进程最大 RSS 中位数
  16,384,000→12,910,592 B。两版输出文件逐字相同且暖命中不改 mtime；测试确认命中不调用 render。
- 惰性预算：512 个文本 ResponseItem 加 64 个工具；无需预算时，历史估算和估算用工具序列化
  各从 50,000 次降为 0；需要预算时两者均保持 50,000 次。所需路径没有加速证据，约 1.4%
  的 CPU 差异不应忽略或声称为零开销。无用路径的 P50 低于计时器分辨率，不解释为零耗时。
  这里没有计入完整 Prompt 克隆、请求构造或网络。
- 历史：100 次扫描行数 95,142,400→12,800，即每次 951,424→128 行；操作
  P50 15.451 ms→10.292 µs。使用逐行唯一编号的 UTF-8/CRLF 文件，并断言读回目标行。
  测到的是真实 ScanCursor、锁和文件扫描，不含历史 JSON 解析；冷查仍从头扫描，追加后仍失效。
  整个探针最大 RSS 中位数两版均 1,982,464 B，没有进程峰值下降证据。
- Shell：每个正文约 8 KiB；17 项负载 JSON 解析 6,800→777，复用比例从 0% 提升至约 88.6%；
  操作 P50 767.208→184.916 µs。输入克隆和完整输出等价断言包含在计时中，
  分配计数包含 Tokio 线程的区间分配，不能视作纯转换函数耗时；峰值没有改善。

## Shell 候选选择与不利场景

下表为相同 400 次重放的 CPU 中位数，单位 ms。所有候选逐次与原无缓存算法输出比较。

| 负载 | 原 LRU | 完全无缓存 | 大集合绕过 | 大集合只读 | 选定的有限接纳 |
|---|---:|---:|---:|---:|---:|
| 暖 16 项 | 50.741 | 106.379 | 50.825 | 50.708 | 50.812 |
| 暖 17 项 | 309.687 | 113.036 | 112.632 | 60.314 | 75.276 |
| 暖 32 项 | 579.174 | 213.278 | 211.911 | 200.461 | 216.225 |
| 暖 128 项 | 2,327.250 | 858.880 | 858.130 | 1,119.552 | 1,117.196 |
| 冷启动后连续重放 32 项 | 579.595 | 214.300 | 212.355 | 215.951 | 216.249 |
| 同一正文重复 32 项 | 101.291 | 212.779 | 213.221 | 216.448 | 101.310 |
| 同一无效 JSON 重复 32 项 | 98.578 | 7.269 | 7.366 | 9.810 | 98.365 |
| 1000 项小输出 | 344.440 | 345.284 | 342.598 | 345.831 | 341.498 |

有限接纳保留小集合、重复正文的命中优势，同时减少顺扫淘汰，并允许新内容逐步进入缓存。
只读方案对已有暖集合更快，但冷集合不能自行建立；绕过方案对 128 项更快，却丢失重复正文收益。
因此选定方案是取舍，不能宣称所有场景最优。32/128 项解析次数分别为
12,800→6,777、51,200→45,177。

大段无效 JSON 在开头即可失败时，完整键哈希/缓存访问比直接解析更贵；本轮保留原负缓存
行为，未解决这个现存问题。高命中率本身不证明 CPU 更低。small1000 的申请量和峰值完全相同，
计时差异很小，不作为收益承诺。候选未采用请求快照，避免额外的按并发请求增长的缓存保留。

## 完整本地应用实验

两版完整 CLI 都从源码以相同 `dev [unoptimized]` 配置构建，固定 V8 sandbox 配置。
每版 7 次独立进程，每次 40 个串行 turn，每个用户输入附加 16,384 字节；模型服务使用
127.0.0.1 固定 SSE fixture。每对样本的完整请求 JSON 仅对明确的生成 ID、时间和隔离状态
路径归一化，随后比较 SHA256；助手输出也完全一致。缺失/null、工具或正文变化不会被忽略。

| 指标 | 基线中位数 | 优化后中位数 | 观察变化 |
|---|---:|---:|---:|
| 整个子进程 CPU，user+system | 2.994588 s | 2.944082 s | −1.69% |
| 每轮 turn P50 的中位数 | 24.008 ms | 22.797 ms | −5.04% |
| 每轮 turn P95 的中位数 | 30.566 ms | 30.324 ms | −0.79% |
| 整个子进程最大 RSS | 200,949,760 B | 200,933,376 B | 基本不变（−0.008%） |

CPU 样本区间分别为 2.888–3.227 s 和 2.856–2.986 s。没有建立统计显著性或通用收益模型；
不能把局部 75%/90% 的 CPU 降幅写成整应用降幅。整进程累计分配未插桩，只有上面的组件
分配数据，不能声称已经证明整应用分配或峰值内存下降。

初始化没有改善证据：原实验优化版首轮约 9.99 s，优化版其余轮初始化约 69.8–77.6 ms。
保留该异常样本后，额外在新路径各启动三次：两版首次分别约 9.25/10.20 s，后续约
83–93 ms。新路径首启等待在两版均可复现，根因未定位，不能归因于本轮优化或删样本掩盖它。

此负载覆盖完整本地请求通道，但不触发 shell 工具历史、TUI viewer 或消息历史导航。
它不覆盖远端网络/模型等待、WS、持续高并发服务器、产品 release 或 Windows。
因此目前可信结论是“特定组件减少重复工作，本地整进程收益较小”，不是所有应用场景加速。
