# 性能后续优化：日志裁剪、跨追加索引与 Markdown 依赖

本文件记录性能审查的第四批设计与验证，基线为
`daf61e7a3d08c004cce53df531094a69795da819`。这三项尚未替换生产算法。
它们与本轮的单模型查询、惰性预算估算、viewer 暖命中、shell 缓存及
相同 revision 的历史锚点优化分开验收。

约束：保持协议、错误处理、输出顺序、持久化格式和跨平台行为；不读取真实凭据，
不调用真实模型服务。实验只使用内存 SQLite、临时文件及现有 Rust 依赖产物。
本文件的次数与等价性结论不代表整应用 CPU、峰值 RSS 或延迟收益。

## 复现与证据边界

从仓库根目录执行：

```sh
python3 scripts/perf_followup_safety.py --max-rows 4 --output /tmp/perf-followup-safety.json
```

可选地指定本仓库已经构建的 `pulldown_cmark` rlib：

```sh
python3 scripts/perf_followup_safety.py --max-rows 4 \
  --markdown-rlib codex-rs/target/debug/deps/libpulldown_cmark-<当前构建哈希>.rlib
```

脚本不启动 Cargo；可选步骤以 `rustc` 链接现有依赖，运行
`scripts/perf_followup_markdown_probe.rs`。若既有产物与当前依赖版本不一致，
应先由统一构建流程更新产物，不把链接失败当作算法失败。

| 验证 | 使用的真实路径 | 能证明的内容 | 不能证明的内容 |
|---|---|---|---|
| 日志 | 当前真实 migrations、从 `prune_global_logs` 原样抽取的 SQL、实际触发器 | 小规模非负安全域等价、负值/溢出反例、剩余行与汇总一致 | SQLx 解码错误、多连接事务等待、生产数据库分布 |
| 历史 | 临时文件实际追加与 EOF 定位；提升门控模型 | 未终止尾行的旧 EOF 锚点不安全；设计门控应保守拒绝 | Rust 文件锁实现、故障注入、跨进程协调、Windows |
| Markdown | 仓库已有 `pulldown-cmark` 真实解析器 | 后方引用定义可改变前方块、first-wins、标签规范化及围栏隔离 | 新依赖图正确性、TUI 样式/布局/复制来源等价 |

`--max-rows 3` 验证 10,140 组非负双限制组合；`--max-rows 4` 验证
60,918 组。所有通过条件是数据和错误断言，不使用机器耗时阈值。

## 一、日志全局裁剪

### 已确认的热点与已完成优化

`codex-rs/state/src/runtime/logs.rs::prune_global_logs` 已通过
`logs_usage_totals` 单行汇总避免每次全表统计。剩余热点是超限后的两个窗口计算：
按 `(ts DESC, ts_nanos DESC, id DESC)` 求累计字节与行号，再删除超限行。
原审查以生产 SQL 测得 200,001 行只需删除最旧一行时仍执行约 1,640 万 SQLite
VM 步。它在原插入事务内运行；这是工作量证据，尚不是多连接锁等待测量。

### 候选算法与成立条件

候选：在同一事务中读取既有总量，从 `(ts, ts_nanos, id) ASC` 索引顺序选取
最旧记录，直到剩余字节和行数同时满足上限，再删除选中的精确集合。

当所有 `estimated_bytes` 是非负整数、累计运算不溢出且汇总正确时，原算法保留
按时间倒序的最长合规前缀，候选删除其最旧后缀，两者等价。零字节可以保留；
达到等号就应停止，不能为了批量处理多删零字节行。仅按 `id` 或插入顺序删除不等价。

真实 schema 没有非负或严格整数存储约束，所以不能无条件使用这个证明：

| 新到旧的字节数 | 限制 | 原 SQL | 不安全边界算法 |
|---|---|---|---|
| `[6, -4, 6]` | bytes=5、rows=100 | 保留 `[-4]` | 保留 `[6,-4]` |
| `[i64::MAX, 1, -i64::MAX]` | bytes=MAX、rows=2 | `integer overflow`，事务失败 | 成功并保留 `[MAX]` |

第二例按旧到新插入，汇总值是 `(1,3)`；汇总在 i64 范围内不证明窗口中间结果安全。
SQLite 的 INTEGER affinity 也允许存储 `0.5` 这样的 REAL 值。不能仅通过 Rust
正常写入路径产生非负值，就把所有已存在数据库视为已满足前提。

### 实施前必须解决的证据缺口

1. 必须取得可靠且足够便宜的安全域证明；不能每次再全表检查后声称已经减少扫描。
2. 对负数、非整数、潜在溢出及不能证明汇总正确的情况，保留原 SQL 和原错误传播。
3. 不允许通过新增 CHECK、清洗历史行、放宽限制、延迟裁剪或修改溢出处理来强行
   满足候选前提。这些会改变既有持久化或错误语义。
4. 若以后设计持久化安全摘要，必须另审 schema 兼容性及额外写入成本，覆盖旧进程
   INSERT/UPDATE/DELETE、迁移、事务回滚和摘要算术。它不属于本批已实施内容。
5. 保留原总量预检查和事务边界；失败不得留下部分删除或错误汇总。

回归应以原 SQL 为 oracle，覆盖相同时间戳、纳秒与 id 决胜、乱序插入、双限制、
边界零字节、超大单条、空库、负值、非整数、溢出及 rollback。随后才测饱和持续写入、
多连接竞争、CPU 时间和事务延迟。成本中高；目前批准的是差分原型研究，不是生产替换。

## 二、跨追加的历史索引复用

### 第一版候选范围

只考虑 `message-history/src/lib.rs` 既有 append 成功路径。保持 lookup 的只读句柄与
共享锁，不写 sidecar、不改变历史格式；Windows、粗粒度时间戳和配置了容量限制的历史
继续禁用索引。相同 revision 的锚点分布优化是独立工作，不要求本设计先实施。

### 提升协议

1. 在取得既有独占文件锁后，从同一个打开句柄取得写前 revision；它必须完整匹配
   缓存的身份、长度、mtime、ctime，不能只比较长度增长。
2. 原文件非空且末字节不是 `\n` 时直接放弃提升。旧扫描可能在第 256 行未终止尾行
   的 EOF 建立锚点；追加会延长该行，旧 EOF 不再是下一行起点。不得补写换行修复它。
3. 可选探测不能改变 append 的成功/失败语义。读取末字节或 metadata 失败时只禁用
   提升；探测后仍执行原 `SeekFrom::End(0)`。
4. 只有原 `write_all`、`flush`、容量处理全部成功且未裁剪，身份与预期长度未发生
   异常变化时，才考虑发布写后 revision。部分写、flush 失败和裁剪一律不提升。
5. 保持 file→cache 锁序，在全局缓存锁外完成文件 I/O。发布时再次核对缓存旧 revision；
   缓存锁 poison 或其他可选缓存故障不得把成功 append 改为失败。
6. 只复用已经验证 UTF-8 的完整行边界，不直接把写入字节数当作已验证的行数。

advisory lock 只能协调遵守锁协议的写者。本方案不能宣称抵御绕过文件锁的原地改写；
外部变化继续依赖现有 revision 检查。它也不能把跨进程追加自动视为本进程受控追加。

### 必须完成的回归

- EOF 恰落 stride 的未终止末行、空文件、UTF-8 边界、合法/非法 JSON 行。
- 写入前 revision 不匹配、同长度重写、替换 inode、追加后异常长度及裁剪。
- 只读 lookup 权限、既有锁竞争/重试行为、不同进程遵守锁协议的追加。
- 部分写、flush、可选 metadata/末字节探测及缓存锁故障；原错误类型和优先级不变。
- Windows 仍走无索引路径；若后续要启用 Windows 索引，应单独设计可靠句柄身份与
  变化代际，并由用户实机验收。

当前脚本只验证 EOF 反例和门控模型，不替代上述 Rust 故障注入与集成测试。
成本中高；未在生产代码中跨追加提升 revision。

## 三、Markdown 块与引用依赖图

### 可以缩小失效范围的前提

不能把“已经输出的块”直接当作稳定块：后方引用定义能改变前方未解析引用；定义
有规范化标签和重复定义 first-wins；列表 tightness、setext 标题、表格、围栏、数学
或不完整标题还会改变块边界与布局。inline visualization 重写还依赖外部片段文件、
可信链接映射和源偏移转换。

拟议事实来源应是同一版本 canonical parser/renderer，而不是单独用正则猜测语法：

- 每个块的原始源范围、布局上下文和最终行范围；最后未稳定块的起点。
- 每个引用定义的规范化 label、源顺序、目标与标题，以及同 label 的有序候选定义。
- 每个使用块引用的 label，**包括当前未解析的 label**，建立反向依赖。
- 外部可视化依赖、文件解析结果/错误状态、宽度、模式、cwd 和链接解析上下文。

若 parser 公共 API 无法准确提供规范化 label、完整定义边界或重写后的源映射，相关
输入继续全文 fallback，不能通过近似解析强行产生局部缓存。

### 候选失效规则

1. append 首先使最后可变块及受其结构影响的后继块失效。
2. 新增/删除/修改/重排定义后重新计算该 label 的 first-wins 定义；只有有效定义
   发生变化时，才传播到所有使用块，包括之前未解析的使用块。
3. 不完整定义、多行标题、围栏或表格重写造成无法证明的源边界，使用 canonical
   全文路径；宽度/模式/cwd/全局链接上下文改变时同样全文失效。
4. 外部可视化文件的出现、消失、同长变化和错误状态改变必须被观察；不能因为正文
   没变就永久缓存。viewer 文档构造提前命中已是独立优化，不能重复计算收益。

### 差分验收矩阵

| 输入维度 | 必须验证的变化 |
|---|---|
| 引用 | 全式/折叠/快捷引用、未解析→解析、重复定义、空白/大小写规范化、转义标签 |
| chunk 切分 | 每个 UTF-8 字符边界、跨块定义、跨 chunk 多行 title、末尾不完整语法 |
| 块结构 | 嵌套列表/引用、tight/loose、setext、表格、未闭合围栏、数学 pending 状态 |
| 可视化 | 围栏中的字面指令、未完成指令、文件不可用→可用、同长修改、可信链接 |
| 环境 | Raw/Rich 切换、宽度变化、cwd/链接上下文变化、归一化造成源映射失效 |

每次 append 后将候选结果与当前完整 renderer 比较，包含文本、样式、超链接目标、
空白、顺序及复制来源；不通过改快照或放宽断言消除差异。内部随机链接占位符不能被
当作稳定缓存身份，应比较已经解析的对外链接语义，并保留现有安全解析过程。

性能断言采用解析字节、解析次数与重建块数，随后在固定负载下测 CPU、分配与延迟。
当前附带 Rust 探针只证明需要这些依赖，不实现增量图，也不替代 TUI canonical 验收。
完整依赖图成本高，现有全文 fallback 必须保留。
